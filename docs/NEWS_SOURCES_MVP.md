# Выбор источников новостей для MVP

## Рекомендация для согласования

Начать с **RSS пресс-релизов Банка России**. Следующим шагом подключить **Минфин и ФНС**, получая из RSS ссылки, а из разрешённых официальных страниц — основной текст. Это решение пока не реализовано. Все проверки и первичные документы: [полный аудит](NEWS_SOURCES_AUDIT.md).

Ветка кода — `feature/backend-mvp`, коммит `0f43e44`. Сейчас новости поступают только из `backend/scripts/seed_demo_news.py`; внешнего сборщика нет. Код API, БД, CSV, `.env` и демо-профили в рамках исследования не менялись.

## Вариант A — минимальный MVP

**Один источник:** [пресс-релизы Банка России](https://www.cbr.ru/rss/RssPress). Канал указан в [официальном каталоге](https://www.cbr.ru/development/RSS/); [правила использования информации](https://www.cbr.ru/About/?PrtId=use) требуют ссылку на первоисточник.

- Проверка: HTTP 200, корректный RSS, 14 записей. У первой записи содержательный description; не требуется HTML-обход для получения этой публикации.
- Собираем заголовок, дату, permalink, имеющийся текст RSS и идентификатор источника. Не обещаем, что description у каждой будущей записи будет полным текстом.
- Темы для показа: решение о ставке, банковское регулирование и финансирование бизнеса. В проверенном срезе есть решение о ключевой ставке от 23 октября 2026 года. Не копировать цифры ставки в промпт/конфигурацию как постоянную величину.
- Источник позволяет показать влияние одного события на CFO и CEO разных отраслей, но не обеспечивает широкий отраслевой поток каждый день.
- Для обычного RSS-запроса ключ и регистрация не потребовались. Это не SLA и не обещание неограниченной частоты запросов. При 403/429 сбор прекращается/откладывается по правилам, обход защиты не используется.
- Сохраняем текст источника отдельно от AI-интерпретации и указываем источник. ЦБ не равен Альфа-Банку: его материалы не превращаются в `bank_opinion`.

**Оценка Backend:** 6–10 рабочих часов на один адаптер, конечный CLI, конфигурацию, нормализацию, insert-only дедупликацию, безопасные тесты и малый приёмочный запуск на отдельной БД. Это предварительная оценка при готовом окружении; применение схем, инфраструктура и интеграция настоящего ML оцениваются отдельно. Реалистичнее всего успеть к ближайшему показу.

## Вариант B — рекомендуемый MVP

| Порядок | Источник и точный URL | Что доступно фактически | Дополнительная работа |
| --- | --- | --- | --- |
| 1 | ЦБ: https://www.cbr.ru/rss/RssPress | Текст ряда пресс-релизов, дата, ссылка | Общая основа сбора и проверка текстового содержимого. |
| 2 | Минфин: https://minfin.gov.ru/rss_news?mod=news&lim=50 | 200, 50 записей; у проверенных description только copyright | Небольшой extractor основной статьи. Одна страница по ссылке проверена: 200 и заголовок/абзацы в HTML. |
| 3 | ФНС: https://www.nalog.gov.ru/rn77/rss/ | 200, 4 записи; у проверенных description нет видимого текста | Extractor статьи, проверка HTTP→HTTPS permalink, локальные тематические фильтры. Одна страница проверена: 200. |

Условия: у Минфина на [главной](https://minfin.gov.ru/) объявлена CC BY 4.0 с исключениями, у ФНС — [отдельная политика](https://www.nalog.gov.ru/rn77/copyright/). Сохранять атрибуцию; не брать исключённые учебные комплекты и данные налоговых интернет-сервисов. Лицензии и допустимый режим внешнего ML зафиксировать в реестре источников до внедрения.

**Покрытие:** финансирование, бюджетная/налоговая политика, таможенные изменения, налоговая отчётность. Это хороший общий фон для B2B, но не полноценное покрытие энергетики, логистики или IT. Проверенный срез ФНС содержит и организационные новости: потребуется отбор по бизнес-содержанию, а не обещание, что каждый элемент полезен клиенту.

**Объём реализации:** ориентировочно 2–3 рабочих дня суммарно, включая вариант A, два ограниченных HTML-адаптера, правила извлечения, тесты и проверку цитат. Если времени меньше, оставить RSS-заголовки в ленте с `text=null`, но не демонстрировать их как полноценную основу анализа. Не заполнять text уведомлением © или пустой разметкой.

**Условные четвёртый и пятый источники:**

- Росстат — https://rosstat.gov.ru/folder/313/rss: 200 и 20 записей; сначала уточнить права и извлечение текста. RSS новостей не заменяет API всех макропоказателей.
- Правительство — http://government.ru/all/rss/: HTTP 200, 20 записей; [условия](http://government.ru/terms/) указывают CC BY 4.0. HTTPS в проверке не установился, анонсы пусты. До решения вопроса доверенного транспорта не включать в основной набор автоматически.

Публичные [правила](https://www.interfax.ru/license) не заменяют лицензию на наш сервис. |

| ТАСС | Широкая повестка; есть RSS и информационные продукты | Преодолеть недоступность только разрешённым каналом поставщика; согласовать [права](https://tass.ru/pravila-citirovaniya). После 403 обхода не делать. |
| РБК и Ведомости | Бизнес и корпоративные события | Официальное разрешение на автоматизацию и наш сценарий хранения/показа/ML. [РБК](https://www.rbc.ru/privacy/), [Ведомости](https://www.vedomosti.ru/info/reprint_rules). Подписка читателя недостаточна. |
| Пресс-центры компаний, например Газпром | Первичные корпоративные заявления; https://www.gazprom.ru/rss/ ответил 200, но запрещён robots | Права проверять по каждому центру. Для Газпрома подходящая лицензия пока не подтверждена, /rss/ закрыт robots: этот поток не подключать без разрешённого канала. Не связывать реальное имя с анонимным ID без допустимого справочника. |

**Работа Backend:** после получения доступа примерно 1–2 дня на один документированный лицензированный поток плюс 0,5–1 день на простой корпоративный RSS и его правила; большой архив, разные схемы и отдельное SLA могут увеличить срок. Срок переговоров неизвестен и не входит в оценку. Этот вариант нельзя обещать к ближайшему показу без уже оформленного доступа; платные обращения не выполнялись.

## Минимальные изменения после подтверждения

1. Заполнить существующий `backend/app/parsers/`, добавить конечный `backend/scripts/collect_news.py`. Новый FastAPI-проект и второй модуль подключения БД не нужны.
2. Добавить только используемые настройки: разрешённые источники, timeout, размер ответа, максимум новых статей, частота, честный User-Agent и режим получения текста. Имена предложить вместе с реализацией, не добавлять фиктивные API-ключи в `.env.example`.
3. Нормализовать данные в существующий `NewsInput`; real → `is_synthetic=false`; `source_url` — оригинальная статья; время с timezone; неизвестное → null. Фиксировать лицензию и атрибуцию во внутреннем реестре.
4. Для A достаточно текущей news-таблицы и стабильного ID. В минимальном режиме изменения публикации с тем же ID не перезаписывать: фиксировать конфликт 409 и продолжать другие элементы. Для обновлений позже согласовать версии и snapshot исходного текста анализа.
5. Состояние HTTP/ETag хранить отдельно от содержимого новости. Не добавлять обязательные поля в API без Frontend. Условия источника могут потребовать показывать автора/лицензию — согласовать, как это передать UI.
6. Один внешний планировщик и один конечный процесс. Никакого сборщика при импорте FastAPI или по одному на каждый uvicorn worker. По умолчанию запуск вручную до приёмки.
7. Сохранённые новости отдавать через имеющиеся news/feed; оценки и разборы — через существующий ML-интерфейс. Не запускать платный анализ каждой записи без бюджета и согласования. Источник регулятора не включать автоматически в банковскую аналитику.

## Приёмка без массового сбора

- До разрешённого сбора: подтвердить права/объём/транспорт/UA, выбранную демо-БД, отсутствие рабочих DSN и секретов в логах.
- Один GET каждого разрешённого RSS: 200, корректный XML, непустые заголовок/ссылка, корректные даты. Для A выбрать 1–3 публикации с реальным текстом; не обходить архив.
- Повтор того же набора → прежние ID, количество news не растёт; изменённый текст не уничтожает прежнюю запись.
- Фикстура проверяет 304, Retry-After при 429, остановку после 401/403, timeout, размер, запрещённые redirects/DTD и robots. Не добиваться реального 429 запросами к сайту.
- GET news/feed возвращают источник, даты и synthetic=false; без оценки лента остаётся chronological. Дата получения не выдаётся за дату публикации.
- ML использует точный сохранённый текст и проверяемые evidence; утверждения выходят с типами fact/model_inference/hypothesis. Фактический эффект на компанию не выдумывается.
- Исходный текст и цитата доступны для проверки; позиция Альфа-Банка берётся только из доверенных банковских материалов. Состояния ошибки не маскируются синтетическим ответом.

## Что решить сейчас

Продакт/аналитик подтверждают вариант A либо B, допустимую давность новости для показа, 3 основных профиля и права/атрибуцию. Backend после этого реализует сбор. ML подтверждает минимальный объём текста, обработку отсутствующих сведений и методику релевантности; Frontend — отображение источника, лицензии, synthetic и отсутствующего score.
