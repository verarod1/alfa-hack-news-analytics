# Банковские PDF: подготовка и запуск ML/RAG

## Что подготовлено на Mac 26.10.2026

В `data/raw/bank_analytics/` скопированы 9 PDF (64 страницы, около 87 МБ)
из локальной папки Downloads. Оригиналы сохранены; SHA-256 каждой копии совпадает.
У всех страниц отсутствует текстовый слой.

Готовый OCR-кэш найден в прежнем ML-коммите `1b6a466`, файл
`data/cache/extracted_text_cache.json`: те же 9 имён, те же числа страниц,
заголовки первых страниц сопоставлены с PDF. Кэш перенесён локально в существующий
формат `data/ocr_cache/<SHA-256 PDF>.json`, без изменения алгоритмов RAG и без OCR.
Старый кэш не содержал хешей PDF: такое сопоставление не является криптографическим
подтверждением каждой распознанной строки; важные цитаты сверяйте с оригиналом.
PDF, распознанные тексты и базы не входят в этот коммит и не появятся после clone.
Для другого компьютера передавайте их только по разрешённому командному каналу.

Рабочий код ML находится в интегрированном `main` и собранном Docker-образе.
`feature/backend-mvp` остаётся Backend-веткой; ML-коммиты в неё не переносились.

## Результат безопасной проверки

- Бесплатная модель `intfloat/multilingual-e5-small` загружена в постоянный кэш.
- Существующий RAG проиндексировал 9 документов / 64 страницы / 349 фрагментов.
- Повторный запуск: `indexed=[]`, `pending=[]`, `documents=9`; JSON-кэш не изменился.
- Поисковый запрос к реальной ChromaDB вернул фрагменты документов с номерами страниц,
  Backend прочитал тот же манифест. Платных OCR/LLM-вызовов — 0.
- После перезапуска Backend и analysis-worker все 349 фрагментов и 64 страницы
  сохранились; worker выполнил поиск офлайн, сервер подтвердил цитату из реального
  документа и сформировал название/страницу для Frontend.
- Целевые тесты RAG-хранилища и подписей источников: 3 прошли. Полный набор не запускался.

## Каталоги Docker

| Назначение | На Mac | В Backend и analysis-worker | Доступ |
|---|---|---|---|
| PDF | data/raw/bank_analytics | /app/data/raw/bank_analytics | чтение |
| OCR и манифест | data/ocr_cache | /app/data/ocr_cache | чтение/запись |
| ChromaDB | data/chroma_db | /app/data/chroma_db | чтение/запись |
| Embedding-модель | data/model_cache | /app/data/model_cache | чтение/запись |

Это bind mounts проекта, а не `/tmp`. Перезапуск контейнеров не удаляет их.
Не удаляйте каталоги кэша для обычного запуска. Готовый кэш совместим с текущим
индексатором; кэш другого формата нельзя просто переименовать.

## Безопасная индексация без платного OCR

Из корня проекта при запущенном Backend:

```bash
docker compose exec backend python -m app.services.rag --limit 9
```

`--allow-ocr` отсутствует: новые сканы без готовых страниц останутся в `pending`.
При первой индексации embedding-модель может скачиваться бесплатно; её кэш сохраняется.
При повторном запуске ожидается `indexed: []`, `pending: []`, `documents: 9`.
Новый PDF обрабатывается отдельно существующим индексатором.

Проверка готового манифеста и количества фрагментов:

```bash
docker compose exec backend python -c 'from app.services.evidence_service import bank_materials; d=bank_materials(); print("Документы:",len(d),"Страницы:",sum(len(x.pages) for x in d))'
docker compose exec -e HF_HUB_OFFLINE=1 backend python -c 'from app.services.rag import get_collection; print("Фрагменты:",get_collection().count())'
```

Ожидается 9 документов, 64 страницы, непустой индекс. Если есть `pending`, не включайте
OCR автоматически: сначала проверьте совместимый кэш и согласуйте расходы с Настей.

## Что нужно Насте для настоящего анализа

В локальном `.env` задайте выданные организаторами `LLM_BASE_URL`, `LLM_API_KEY`
и согласованный `LLM_MODEL`. Для существующей интеграции:

```dotenv
ML_ADAPTER_MODULE=team_ml.adapter
```

Пути RAG уже заданы Compose. `DOCKER_BANK_MATERIALS_PATH` обычно оставляют пустым:
Backend читает автоматически созданный `data/ocr_cache/bank_materials.json`.
Настоящие значения ключей не публикуйте. Сейчас ключ/адрес отсутствуют, ML отключён.

Только после согласования реальных расходов примените настройки контейнеров:

```bash
unset ML_ADAPTER_MODULE LLM_API_KEY LLM_BASE_URL
BACKEND_PORT=8001 docker compose up -d --no-build --no-deps backend analysis-worker
```

После включения worker может обработать уже накопленную очередь анализов — это
реальные ML-запросы. Сначала проверьте очередь и бюджет. Перезапуск хостового Python
или frontend не применяет настройки к уже работающему Backend-контейнеру.

Для будущих сканов, у которых нет кэша, отдельное разрешённое действие:

```bash
docker compose exec backend python -m app.services.rag --limit 1 --allow-ocr
```

Это платное распознавание одного нового/изменённого документа, не одной страницы.
Для нынешних девяти документов повторный OCR не нужен.

## Результат во Frontend

Backend уже передаёт проверенные `document_id`, название, страницу, цитату и URL.
Для локальных PDF `url=null`: публичная ссылка не выдумывается. Интерфейс может
показать название, страницу и цитату; открытие самого локального PDF по веб-ссылке
не реализовано. Для кликабельного внешнего источника нужен подтверждённый адрес.
Совпадение цитаты с OCR-текстом проверяется сервером, но не гарантирует безошибочность
самого распознавания. Материал 2021 года остаётся историческим, его дату не обновляли.
