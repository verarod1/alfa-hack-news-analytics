периодический сбор. Старая дата не заменялась датой импорта. NEWS_MAX_AGE_DAYS

Без ML-оценок порядок — published_at DESC, NULL в конце. При оценках сначала score,

не более 5 записей на источник за цикл, без ML/очистки. В env.example NEWS_LIMIT=3.

## API и Frontend

Маршруты/методы/параметры и X-Company-ID в API-клиенте main совпадают с Backend.
nginx проксирует `/api/` в backend:8000, Vite использует VITE_DEV_API_TARGET
(по умолчанию localhost:8000). Для Backend на 8001 локальный Vite требует настройки
этого target; для Docker nginx это не нужно. CORS по умолчанию разрешает localhost:3000
и 127.0.0.1:3000, прокси Docker работает с тем же origin.

В Frontend не найден вызов `/companies/{id}/relations` и `/my-analyses`:
эти API готовы, но UI связей/списка анализов нужно отдельно подключить frontend-разработчице.
Банковские баланс/операции на домашнем экране демонстрационные, не данные PostgreSQL.
Backend не расширяет доступ ко всем клиентам ради UI: основной набор — три компании.

## PDF, OCR и источники анализа

Проверенный локальный путь `data/raw/bank_analytics/` отсутствует, PDF=0, готового
манифеста нет, LLM-ключ и ML-модуль в локальном .env не заданы.
Это не позволяет заявлять реальную банковскую аналитику или успешный OCR сканов.

Существующий RAG лениво загружает embedding-модель, хранит Chroma/OCR отдельно,
извлекает текстовые PDF, для сканов без разрешённого OCR оставляет pending.
Платный OCR требует отдельного --allow-ocr. Его в этой работе не запускали.

Минимально исправлены подписи evidence: заголовок новости и название банковского
документа берутся из проверенных серверных данных после проверки URL/страницы/цитаты.
Backend передаёт sources с document_id/document_title/page/quote/url и bank_opinion;
Frontend уже умеет показывать подписи, страницы и ссылки. Для локального PDF URL=null:
публичная ссылка не выдумывается. Для кликабельного источника нужен проверенный URL
в доверенном BANK_MATERIALS_PATH. Ошибочная ссылка/цитата отклоняется.
