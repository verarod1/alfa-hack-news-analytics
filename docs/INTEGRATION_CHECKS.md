## Что исправлено при объединении

- Согласован `.env.example`, сохранены настройки парсера и пути `data/raw` ML-ветки.
- ML-профиль использует существующий PostgreSQL mapper, без второго чтения CSV,
  потери null и выбора первой неоднозначной записи.
- Ранкер получает полный профиль, роль и новость. Отдельный `rank_news.py` ограничен
  1–20 новостями, вызывает существующий ML-интерфейс через gateway и сохраняет через
  `news_service.save_relevance`. Контекст ответа проверяется до сохранения.
- Ошибка/пустой JSON/неполный ответ LLM не превращаются в `0.5`, придуманную причину,
  завершённый анализ или успешное сообщение `{}`. Старые оценки при ошибке остаются.
- Модели, лимиты и таймауты берутся из конфигурации; SDK создаётся только при вызове.
  Автоматические повторы SDK выключены, gateway ограничивает время процесса.
- Адаптер анализа использует проверенные RAG-фрагменты и проверяет DTO, компанию,
  новость, страницу и дословную цитату. Государственный источник не считается позицией банка.
- Чат получает профиль, новость, историю и подтверждённые страницы банка;
  ответы могут ссылаться только на уже проверенные источники анализа.
- Chroma, OCR и embedding-кэш вынесены из `/tmp` в постоянные writable mounts.
  PDF/CSV остаются read-only. Индексация не запускается из HTTP-запроса.
- PDF дедуплицируются по содержимому; страницы кэшируются до индексации,
  новые документы добавляются в непустую коллекцию. Параллельные индексаторы
  защищены файловой блокировкой. Повторный OCR требует новых некэшированных страниц
  и явного `--allow-ocr`. Старые кэши/коллекции не удаляются.

## Граница подтверждённых ML-проверок

Тесты используют временный PostgreSQL, настоящий subprocess gateway и ML-адаптер.
Только ответ генеративного сервиса заменён явно. Проверены разные оценки по
компании/роли, порядок ленты, фильтр risk по завершённому анализу, состояния задач,
чат и история. Проверки цитат отклоняют неподтверждённый текст.

Качество реального ранжирования, бизнес-инсайтов и распознавания сканов не проверялось:
платных вызовов не было. В `data/raw/bank_analytics` нет реальных банковских PDF.
Для содержательной проверки RAG команда должна предоставить разрешённые документы,
проверить OCR-текст и исходные ссылки, подготовить индекс, согласовать бюджет
и выполнить ограниченный запуск с действующим ключом.
