# Аудит источников новостей для Backend

## Решение

Для первой автоматической демонстрации выбрать **RSS пресс-релизов Банка России**. Для следующей версии — **Банк России + Минфин + ФНС**, после согласования ограниченного извлечения текста официальных страниц двух последних ведомств. Их RSS подходят для обнаружения публикаций, но не дают достаточного текста для содержательного AI-анализа.

Это исследование и предложение, не запуск сборщика. Рабочие API, настройки, PostgreSQL, CSV и демо-профили не изменены. Созданы только три Markdown-документа. Договоров и разрешений от редакций не получали. «Берём» означает рекомендацию к согласованию и реализации, а не уже подключённый источник.

## Метод проверки и пределы доказательств

- Срез кода: ветка `feature/backend-mvp`, HEAD `0f43e447d5a92f300ef9dce4e0c960e0a65f2538`. В старом `docs/BACKEND_MVP.md` осталось прежнее имя ветки; фактически активна `feature/backend-mvp`.
- Проверены все 14 обязательных сайтов, дополнительно корпоративный пресс-центр Газпрома и Росрыболовство. Для недоступных сайтов подтверждена только недоступность из этого окружения, а не отсутствие RSS или запрет для всех пользователей.
- Использовались единичные обычные GET с честным User-Agent `NewsAnalyticsSourceAudit/1.0`, без cookies авторизации, ключей, браузерной автоматизации, прокси, отключения TLS-проверки и обхода CAPTCHA/WAF. Ограничение ответа — примерно 1,5 МБ, у robots — 300 КБ; массового обхода статей не было. В параллели проверялись разные сайты, внутри сайта — последовательно.
- Проверялись robots, официальные страницы каналов и условия. Исключение в последовательности: один GET RSS Газпрома выполнен до сопоставления запрета /rss/ с точным путём; при итоговой сверке ошибка обнаружена, повторных запросов не было, источник исключён. Первичный Python-клиент на части HTTPS не смог проверить цепочку сертификата; проверки повторены обычным `/usr/bin/curl` с системной проверкой TLS. Ошибка локального trust store не записана как блокировка сайта.
- Web-поиск использован для официальных документов. Его ошибки `Unsupported content-type`/`Internal Error` не являются HTTP-статусами сайта. Например, XML ФНС не читался web-инструментом, но обычный curl вернул 200 и корректный RSS.
- Одно успешное обращение не доказывает стабильность, отсутствие будущих блокировок, полноту архива или частоту обновления. Риск — наша инженерная оценка, а не гарантия издателя. Интервалы опроса ниже — предложение, не лимит поставщика.
- «Нет HTTP» означает сбой до получения HTTP-ответа; это не код 000/403. 401 не доказывает, что регистрация действительно решит проблему. Числовые лимиты запросов и SLA для публичных RSS не найдены; их отсутствие в документации не означает безлимитный доступ.
- robots оценивается по конкретному пути и User-Agent с учётом wildcard/конечного `$`. В частности, `Disallow: /?` у Коммерсанта не означает запрет всех URL: `/RSS/news.xml` не совпадает с этим шаблоном. robots не лицензия на использование текста.

| Вход | `schemas/news.py:NewsInput`: id/title обязательны; text/published_at/source_* могут быть null; дата с timezone; is_synthetic обязателен. URL — HTTP(S), без credentials. |
| Хранилище | `backend/db/mvp.sql`, таблица news: id TEXT PK; title TEXT NOT NULL; text TEXT; published_at TIMESTAMPTZ; source_id/name/url TEXT; created_at TIMESTAMPTZ DEFAULT now(); content_hash TEXT UNIQUE NOT NULL; is_synthetic BOOLEAN NOT NULL. | Конфликты | `repositories/news_repository.py:5`: INSERT ON CONFLICT DO NOTHING и SELECT по id или hash. При том же hash возвращается существующая запись; прежний id с новым hash → 409 NEWS_CONFLICT. UPDATE новости не реализован. URL сам по себе не UNIQUE. |
| HTTP API | `api/routes/news.py`: GET /api/v1/news/{id} и /feed; публичного POST загрузки новостей нет. В repository есть list_news; запись — внутренним save_news. |
| Персонализация | `news_relevance` — company_id/role/news_id, score/reasons/method/version. Feed сортирует score до пагинации; без оценок — chronological. Связь новости с компанией не создаётся RSS автоматически. |
| Анализ | analyses.news_id — FK news; компания и роль хранятся в задаче. ML получает серверную NewsResponse через AnalysisContext. Реальная модель не подключена автоматически. |
| Источники | `evidence_service.py:40 verify_sources` проверяет URL/ID и наличие цитаты в news.title + news.text. Эта проверка не доказывает истинность публикации, её лицензию или смысловой вывод модели. |
| Позиция банка | `verify_bank_opinion` требует bank_analytics из локального доверенного манифеста с document/page/quote. Новости ЦБ/ФНС не являются позицией Альфа-Банка. |
| Настройки | В settings.py нет реестра news feeds, интервала сборщика или ограничений скачивания. DATABASE_URL и ML-настройки уже есть; новый модуль подключения БД не нужен. |

CSV изучены только локально, построчно: структура компаний — SYNTHETIC_U/CL_TYPE/MAINOKVED_CODE/MAINOKVED_NAME и признаки; платежей — PAYER/BENEFICIARY/PAY_AMT/PAY_CNT; связей — SYNTHETIC_F/SYNTHETIC_U. В этом отчёте нет исходных строк CSV, финансовых значений, физических лиц, групп и платежей. В `raw_*` ничего не записывалось.

## Права на хранение и показ

Это вывод по опубликованным условиям, а не полученное индивидуальное разрешение. Для неясных случаев выбран режим «не загружать до уточнения». Нельзя автоматически считать заголовок/анонс свободным от всех ограничений. Анализ во внешнем LLM, индексирование и обучение модели — разные способы использования: право на цитирование не является общим разрешением на них.

Число символов всей HTML-страницы нельзя выдавать за длину статьи.

Наблюдались 401/403, TLS/connection timeout и ограничение размера; 429 в этих запросах не получен. Обязательная авторизация, геоблокировка и конкретная причина WAF-отказа не доказаны. У ЦБ сервер сообщает DDoS-Guard, у Интерфакса/Коммерсанта — QRATOR, но запросы RSS прошли; наличие защитного сервиса не означает текущую блокировку. Слово captcha внутри скрипта HTML не считается показанной CAPTCHA.

| РБК | robots 200, ряд поисковых/служебных URL запрещён. robots не отменяет запрет автоизвлечения из правил и 401 главной. RSS-host отдельно не проверялся. |

Частоту публикаций можно оценить лишь по датам текущей выборки: например, у ЦБ/Минфина первые новости от 23 октября, у ФНС — несколько за 23 октября, у правительства — 24 октября, у Росстата — 22 октября. Это не расписание и не доказательство ежедневного пополнения. Во всех девяти RSS поле ttl не найдено. Для MVP предлагаем опрос 30–60 минут, один запрос на источник за запуск, для скачивания новых официальных статей не более нескольких разрешённых страниц; значения уточнить и вынести в конфигурацию. Один источник не должен блокировать остальные.

## Покрытие бизнес-тематик

Это оценка применимости, не утверждение о наличии каждой темы в сегодняшнем RSS. «После разрешения» не входит в гарантированный текущий MVP.

| Тема | Приоритетные источники | Ограничение покрытия |
| --- | --- | --- |
| Ключевая ставка | ЦБ пресс-релизы | Редкие решения, нельзя обещать новую новость каждый день. |
| Налоги и законодательство | ФНС, Минфин; акты на publication.pravo после проверки доступа | Новость ведомства не заменяет проверку текста, даты вступления и адресатов нормы. |
| Государственное регулирование | Правительство условно; ФАС/Минпромторг после доступа | Сейчас подтверждён только ограниченный набор работающих каналов. |
| Валюты и макроэкономика | ЦБ; Минфин; Росстат условно | Курсы — структурированные данные, не новостной инсайт сами по себе. |
| Промышленность | Минфин/правительство о мерах поддержки; Минпромторг после доступа | Базовые три источника дают косвенное, не полное отраслевое покрытие. |
| Логистика и поставки | Минфин по таможне; правительство условно; СМИ по лицензии | Нет проверенного специализированного транспортного потока в базовом наборе. |
| Импорт и экспорт | Минфин по таможенному регулированию; ЦБ по валютам | ОКВЭД оптовика не доказывает импорт; FTS_FLAG не описывает конкретный контракт. |
| Сырьевые цены | Договорные СМИ/корпоративные сообщения; ЦБ XML для драгметаллов | Не проверен полный рынок сырья; нужны отдельные источники и права. |
| Энергетика | Газпром только после разрешённого канала; правительство; СМИ с правами | Пресс-релиз — позиция компании, а не независимое подтверждение всей отрасли. |
| Строительство и недвижимость | Правительство условно; Минфин; СМИ с правами | Нет подтверждённого регулярного отраслевого RSS в базовых трёх. |
| Розничная торговля | ФНС/Минфин, ЦБ по финансированию | Для изменений спроса и конкретных сетей нужны дополнительные данные. |
| Технологии и IT | Минфин/ФНС по цифровизации; корпоративные центры условно | Слабее отраслевого IT-потока; не обещать новости об ИТ-льготах без конкретной публикации. |
| События у контрагентов | Пресс-центр реального эмитента, лицензированные СМИ | В CSV анонимные ID и нет подтверждённого соответствия реальным именам/ИНН. Автоматическая привязка сейчас невозможна. |
| Корпоративные события и финрезультаты | Официальные корпоративные раскрытия/пресс-центры после аудита, СМИ с правами | Не сопоставлять Газпром с выдуманным SYNTHETIC_U; аудировать каждый центр отдельно. |

Дополнительный официальный ресурс: [XML ЦБ](https://www.cbr.ru/development/SXML/) документирует `/scripts/XML_daily.asp` и данные драгметаллов. Это предложение для контекста ML, не подтверждённый этим аудитом HTTP-поток: сами XML-endpoint курсов/металлов не запрашивались. Не превращать изменение курса в придуманную публикацию СМИ. Дополнительный рыбный RSS и RSS Газпрома отклонены из-за robots. Права на текст и техническое наличие RSS не снимают ограничение на доступ к пути.

## Минимальная архитектура после согласования

1. Использовать существующий `backend/app/parsers/`; пустые файлы заполнить только после отдельного задания. Общий HTTP-клиент и RSS-нормализация, отдельные конфигурации/небольшие адаптеры ЦБ/Минфина/ФНС. Для двух HTML-источников — явные правила извлечения основного текста, без обхода сайта. Отдельная команда `backend/scripts/collect_news.py` как конечный запуск, без сети при импорте модуля и без фонового цикла в каждом uvicorn worker.
2. Запускать один экземпляр по внешнему cron/systemd timer/планировщику после согласования, например каждые 30–60 минут. Это предложенное расписание. При параллельном запуске — короткая advisory lock только сборщика, без блокировки чтения news и без использования блокировки CSV-импортёра.
3. Конфигурация: allowlist URL, enabled, режим rss_only/rss_and_article, interval, timeout, max_response_bytes, max_new_articles, User-Agent, разрешённый объём текста и дата/URL условий. Хранить в конфигурационном файле/окружении, не в HTTP-вводе пользователя. Секретные договорные ключи — только env; не добавлять фиктивные ключи для открытого RSS.
4. Защита сети: только allowlist схем/хостов/путей; запрет credentials, локальных/служебных адресов, проверка DNS и каждого redirect, включая ссылки из RSS; ограничить redirects и объём, не скачивать картинки/PDF автоматически. Валидатор NewsInput сам по себе SSRF не предотвращает. XML парсить с отключёнными внешними сущностями/DTD и лимитом размера; очищать HTML в безопасный текст. Содержимое — недоверенные данные для ML, не инструкции.
5. Поля: source_id — устойчивый slug издателя, source_name — фактическое название, source_url — permalink конкретной публикации, не URL RSS. GUID сохранять отдельно от URL. id — детерминированный строковый `news_<hash(source_id, guid-or-canonical-url)>`. Реальные новости — is_synthetic=false; даты публикации неизвестны → null, не now(). Даты с явным offset переводить в UTC; timezone без указания не угадывать без правила конкретного источника. created_at — время сохранения, не публикации.
6. Дедупликация в минимальном MVP: стабильный id и исходный permalink, один news_service.save_news. Повтор неизменённой записи — no-op. Исправленный текст с прежним id сейчас даст 409: не обходить это случайным новым ID и не падать всем запуском. Зарегистрировать конфликт и сохранить старый текст до согласованной политики версий. Похожие новости разных редакций не сливать только по заголовку или сходству; кластеризацию событий оставить ML.
7. Обновления после отдельного согласования: добавить внутренние source_item_id/canonical_url/fetched_at или отдельную запись ingestion, уникальность (source_id, source_item_id), наблюдённый хеш и проверку обновлений. Если разрешить обновление новости, нужен version/snapshot текста для существующего анализа: evidence сейчас проверяется по текущей news и изменение текста может обесценить старые цитаты. Для первого показа достаточно insert-only + отчёта конфликтов; бесконтрольный UPDATE нельзя добавлять как «маленькое улучшение».
8. Для одного конечного запуска сохранять ETag/Last-Modified и состояние источника вне news. При 304 ничего не менять, при 429 соблюдать Retry-After, при 401/403 остановить источник и сообщить оператору, при timeout/5xx применить ограниченный backoff с jitter; не повторять немедленно и не обходить WAF. При недоступном/запрещающем robots — приостановить новый сбор до разбора. Не стирать старые новости и не включать --replace.
9. Сохранить действующий API без новых обязательных полей. Для сохранения лицензии/атрибуции использовать внутренний реестр source_id; выводить название/ссылку, а для CC — доступное пользователю пояснение лицензии и изменений. Если требуется автор/лицензия в JSON — согласовать добавление необязательного поля отдельно, сейчас контракт этого не гарантирует. Реестр не заменяет сохранение автора, когда он обязателен по условиям СМИ.
10. После сохранения новость доступна news/feed; сама по себе она не создаёт персональную оценку или completed-анализ. ML получает существующий AnalysisContext; отдельно согласовать batch оценки company/role/news и общий бюджет. Не запускать платный анализ автоматически на каждую публикацию. Для короткого RSS text=null и limitation о недостатке текста; не выдавать вывод по одному заголовку за подтверждённый факт.
11. Новости ЦБ, Минфина, ФНС и компаний — Evidence.type=news. Не загружать их автоматически в bank_materials и не повышать до bank_opinion. Позиция Альфа-Банка — только отдельный доверенный документ с подтверждёнными page/quote/evidence. RAG и методика релевантности остаются работой ML.
12. Тесты без внешней сети: RSS fixture с timezone/пустым description, повтор/конфликт обновления, разрешения/атрибуция, 304/429/403, неверный XML/URL/redirect. Интеграцию сохранения — на временной PostgreSQL. Первый приёмочный сетевой запуск — малый согласованный набор без записи в рабочую БД.

## Приоритеты и критерий выбора

- P0: согласовать вариант A и источник; не обещать персональную ленту до ML; не подключать редакции по одному факту наличия RSS.
- P1: B из трёх ведомств, ограниченный extractor и сохранение исходного текста/ссылок; договориться о версии новости и атрибуции. Расширение на Росстат/правительство только после закрытия условий/HTTPS.
- P2: договорные СМИ, отраслевые и корпоративные источники, кластеризация и обновление версий; подлинная привязка реальных эмитентов к анонимным компаниям требует отдельного допустимого справочника.

## Дата проверки и непроверенные сведения

Дата проверки: **24 октября 2026 года**, временные отметки HTTP — UTC в журнале выше. CSV/БД не загружались, рабочая PostgreSQL не опрашивалась. Парсеры не реализованы, commit/push не выполнялись.
