# ML Core: Интеллектуальный анализ новостей

Этот модуль является ML-ядром проекта **Alfa Hack News Analytics**. Он отвечает за генерацию персонализированных бизнес-инсайтов на основе новостей, поиск по базе знаний банка (RAG), ранжирование ленты и интерактивный чат.

Модуль спроектирован так, чтобы бесшовно интегрироваться с готовым Backend API через строгие Pydantic-контракты.

##  Ключевые возможности

1. **Анализ новостей (`adapter.py` -> `analyze`)**:
   * Оценивает влияние события на конкретную компанию с учетом ее профиля (отрасль, регион, банковские продукты) и роли пользователя (CEO/CFO).
   * Генерирует структурированный JSON: риски, возможности, рекомендации и факторы компании.
2. **RAG (Retrieval-Augmented Generation) (`rag.py`)**:
   * Автоматически распознает новые PDF-документы (аналитика банка) с помощью **Qwen3-VL-30B-A3B-Instruct** (Computer Vision).
   * Векторизует текст через `intfloat/multilingual-e5-small` и сохраняет в **ChromaDB**.
   * Находит релевантные куски текста для обоснования позиции банка (`bank_opinion`).
3. **Чат с пользователем (`adapter.py` -> `chat`)**:
   * Отвечает на уточняющие вопросы пользователя, опираясь строго на контекст уже проведенного анализа.
   * Возвращает `evidence_ids`, ссылаясь на проверенные источники.
4. **Ранжирование (`ranker.py`)**:
   * Оценивает релевантность новости для конкретной компании и роли по шкале от 0.0 до 1.0. Сохраняет оценки в базу, чтобы Backend мог сортировать ленту (`ranking_mode="relevance"`).

##  Технологический стек и Модели
* **LLM для анализа и чата**: `GLM-5.3-Flash`, `Qwen3.6-35B-A3B` (разрешены по ТЗ).
* **CV для OCR PDF**: `Qwen3-VL-30B-A3B-Instruct` (разрешена по ТЗ).
* **Векторная база**: ChromaDB.
* **Эмбеддинги**: SentenceTransformers (`multilingual-e5-small`).
* **Кэширование**: Встроенный кэш в `llm_client.py` экономит до 90% бюджета на API.

##  Архитектура и обход ограничений
* **Защита от галлюцинаций**: Все ответы проходят через санитайзер (в `adapter.py`). Если модель придумывает несуществующую цитату банка, `bank_opinion` принудительно ставится в `null`.
* **Изоляция Docker**: Так как в `docker-compose` папка `data` смонтирована как `:ro` (read-only), ChromaDB и кэш OCR сохраняются в системную папку `/tmp` (`tempfile.gettempdir()`). Это позволяет запускать код и локально, и в контейнере без ошибок доступа.

##  Как запустить

**1. Запуск через Docker (рекомендуется):**
```bash
# Пересобрать контейнер (если менялись зависимости)
docker compose up -d --build backend

# Запустить обработку очереди анализов
docker compose exec backend python scripts/process_analyses.py --limit 1

# Запустить обработку конкретного анализа
docker compose exec backend python scripts/process_analyses.py --analysis-id <ID>

**2. Локальный тест ML-адаптера (без API):**

python backend/team_ml/adapter.py


#  Бюджетирование
Благодаря оптимизированным промптам и кэшированию, один полный цикл анализа (включая RAG и генерацию JSON) обходится менее 0.05 ₽. Дневной лимит в 500 ₽ позволяет обработать до 10 000 новостей без риска превышения бюджета.
