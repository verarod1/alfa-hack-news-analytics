#  ML Core: Интеллектуальный анализ новостей

Этот модуль является ML-ядром проекта **Alfa Hack News Analytics**. Он отвечает за генерацию персонализированных бизнес-инсайтов на основе новостей, поиск по базе знаний банка (RAG), ранжирование ленты и интерактивный чат.

Модуль спроектирован так, чтобы бесшовно интегрироваться с готовым Backend API через строгие Pydantic-контракты, и включает встроенную защиту от галлюцинаций нейросети.

##  Ключевые возможности

1. **Анализ новостей (`adapter.py` -> `analyze`)**:
   * Оценивает влияние события на конкретную компанию с учетом ее профиля и роли пользователя (CEO/CFO).
   * Генерирует структурированный JSON, который проходит строгую валидацию бэкенда (`AgentAnalysisOutput`).
2. **RAG (Retrieval-Augmented Generation) (`rag.py`)**:
   * Использует **манифест** (`bank_materials.json`) для точного сопоставления цитат и страниц документов.
   * **Автоматически** распознает новые PDF-документы (сканы) с помощью **Qwen3-VL-30B-A3B-Instruct** при первом запросе.
   * Векторизует текст через `intfloat/multilingual-e5-small` и сохраняет в **ChromaDB**.
3. **Чат с пользователем (`adapter.py` -> `chat`)**:
   * Отвечает на вопросы, опираясь строго на контекст уже проведенного анализа.
   * Ссылается только на проверенные источники (`evidence_ids`).
4. **Ранжирование (`ranker.py`)**:
   * Оценивает релевантность новости для компании и роли по шкале от 0.0 до 1.0.

##  Архитектура и работа с PDF

**Автоматическая индексация (Lazy Initialization):** Система полностью автономна. При первом запросе на анализ новости RAG-модуль сканирует папку `data/raw/bank_analytics`. Если он находит новые PDF-файлы, он автоматически распознает их через OCR, сохраняет в кэш и индексирует в ChromaDB. Никаких ручных команд запускать не нужно.

* **Защита от галлюцинаций**: Все ответы проходят через санитайзер. Если модель придумывает цитату, бэкенд отклонит результат, а адаптер вернет безопасную заглушку (без падения в ошибку `ML_RESULT_INVALID`).
* **Хэширование**: Файлы PDF идентифицируются по SHA-256. Если вы добавите новый файл, система проиндексирует только его. Если файл не менялся — повторного списания денег за OCR не будет.
* **Docker Volumes**: Папки `data/chroma_db` и `data/ocr_cache` проброшены в Docker с правами на запись, чтобы база и кэш сохранялись между перезапусками контейнера.

## Как запустить

**1. Пересборка и запуск Docker:**

docker compose up -d --build backend

##2. Запуск анализа и чата:##


# Обработка очереди анализов (RAG сам спарсит нужные PDF при первом запросе)

docker compose exec backend python scripts/process_analyses.py --limit 1

# Бюджетирование
Благодаря оптимизированным промптам, хэшированию и кэшированию, один полный цикл анализа обходится менее 0.05 ₽. Дневной лимит в 500 ₽ позволяет обработать до 10 000 новостей. Распознавание сканов (OCR) выполняется один раз при добавлении нового файла и стоит около 15 копеек за пакет документов
