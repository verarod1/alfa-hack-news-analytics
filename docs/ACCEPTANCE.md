# Проверка основного сценария

Актуализировано 26.10.2026. Запуск — по README, отдельный compose.review.yml.

1. Открыть http://localhost:3100/demo: доступны три компании и по две роли.
2. Выбрать компанию и CFO: открывается профиль и лента с новостями [ТЕСТ].
3. Открыть новость и запустить разбор: queued → running → completed. Ответ прямо сообщает, что он синтетический.
4. Проверить источники и ход разбора, открыть сохранённые разборы.
5. Задать вопрос в чате: появляется синтетический ответ со ссылкой на основание.
6. Переключить компанию/роль: контекст меняется. Прямой запрос чужой компании с X-Company-ID исходной компании возвращает 403.
7. Выполнить `docker compose -f compose.review.yml --profile check run --rm smoke`: ожидается PASS. Скрипт проверяет шесть профилей, ленту, scope, идемпотентность, обработку очереди, источники, чат и сохранение.
8. Остановить и повторно запустить стек: данные должны сохраниться.

Настоящее качество AI проверяется отдельно в обычном Compose: разрешённые CSV, доступный провайдер и ключ, team_ml.adapter. Проверить связь вывода с профилем, источниками новости и документами банка. Отсутствие PDF не должно порождать позицию банка. Сетевые ошибки и отсутствие ключа не являются успешным AI-разбором.

Диагностика: `docker compose -f compose.review.yml ps` и `docker compose -f compose.review.yml logs --tail=100`. Ошибка сборки требует проверки доступа к пакетным реестрам. /health подтверждает процесс API; проверочный healthcheck дополнительно требует шесть профилей из БД.
